# @kuiralabs/midnight-contract

Contracts for the Midnight CLI packages: deploying, calling and reading a Compact contract from its dApp folder, the requests a deploy or a call is built from, a compiled contract's circuits and witnesses, and the chain's block limits. A deploy or a call is proved and paid through a payer you pass (connect's `servePayer`, which runs it through `mn serve`); its contract script runs under Node.js, also when your program runs under bun.

## Install

```sh
npm install @kuiralabs/midnight-cli-core@next @kuiralabs/midnight-contract@next @kuiralabs/midnight-connect@next @kuiralabs/midnight-engine-rc@next
```

Every package is a release candidate on the `next` tag. Install with npm 11 or older (npm 12 no longer reads a package's shrinkwrap): each engine ships an `npm-shrinkwrap.json` that pins its SDK set, and npm 11 honours it. A program that runs the SDK installs an engine: `@kuiralabs/midnight-engine-rc` for preprod, preview and a local network, `@kuiralabs/midnight-engine-beta` for stagenet. How a program sets up its process for the SDK (the rejection guard, the heap, Ctrl-C, ending) is in [core's README](https://github.com/kuiralabs/midnight-cli/blob/main/packages/cli-core/README.md#your-process-what-mns-shell-does-that-you-must-do).

## Entry points

| Import | What it holds |
|---|---|
| `@kuiralabs/midnight-contract` | The functions below, and the errors they throw (`ContractNotCompiledError` among them) |
| `@kuiralabs/midnight-contract/commands` | `contract` (inspect, deploy, call, state) and `inspect-cost` as a registry entry (`contractCommands`), its codes (`contractCodes`) |

Every export and its signature is in [api-report.md](https://github.com/kuiralabs/midnight-cli/blob/main/packages/contract/api-report.md).

## What you call

- `deployContract`, `callContract`: deploy or call a compiled contract, paid by the payer you pass; they return receipts.
- `readContractState`, `contractExists`: a deployed contract's state.
- `findContractInfo`: a compiled contract's circuits and witnesses, from its `managed/` folder.
- `contractDeployRequest`, `contractCallRequest`: the requests a deploy or a call is built from, without sending them.

## Codes

Each error carries a `code`, and `classifyError(err, registry)` gives its code and exit code by that code alone, never by its message. These are the codes this package owns; the rest come from core and the packages below it, each listed in its README.

<!-- codes: generated by npm run package-readmes -->
| Code | Exit | What went wrong | What to do |
|------|------|-----------------|------------|
| `NO_NODE_RUNTIME` | 1 | Contract scripts run under Node.js, and none was found on PATH. | Ask the user to install Node.js 22 or later, or to run mn under Node. |
| `CONTRACT_NOT_COMPILED` | 1 | No compiled contract was found where the command looked (managed/<name>/compiler/contract-info.json). | Ask the user to compile the contract (compact compile), or pass the dApp folder (path) or the managed folder (managed). |
| `CONTRACT_INFO_INVALID` | 1 | A compiled contract's contract-info.json is not what the Compact compiler writes (not JSON, or its circuits or witnesses missing or malformed). | The message names what is wrong: ask the user to compile the contract again (compact compile). |

## Mounting its commands

The commands are definitions your program mounts in its own command line, with your state root, settings and notices (core's README explains each part). Its commands name codes the packages it builds on own, so the registry holds their entries too, as mn's does; a registry missing one is refused when it is built. Built on core's example, this one adds the contract commands, and connect's payer for the deploys and calls:

```js
import { homedir } from 'node:os';
import { join } from 'node:path';
import { classifyError, createHost, createPackageRegistry, parseArgs, runCommand, settingsFromEnvironment, UsageError } from '@kuiralabs/midnight-cli-core';
import { coreCommands } from '@kuiralabs/midnight-cli-core/commands';
import { chainCommands } from '@kuiralabs/midnight-chain/commands';
import { walletCommands } from '@kuiralabs/midnight-wallet/commands';
import { contractCommands } from '@kuiralabs/midnight-contract/commands';
import { servePayer } from '@kuiralabs/midnight-connect';
import { createRcEngine } from '@kuiralabs/midnight-engine-rc';

const registry = createPackageRegistry([coreCommands, chainCommands, walletCommands, contractCommands], []);
const host = createHost({
  paths: { stateRoot: join(homedir(), '.my-app'), home: homedir() },
  settings: () => settingsFromEnvironment(process.env),
  notice: (line) => console.error(line),
  engineLoader: async (_set, host) => createRcEngine(host),
});
const output = { result: (data) => console.log(JSON.stringify(data)), stdout: (text) => process.stdout.write(text), stderr: (text) => process.stderr.write(text) };

const args = parseArgs(process.argv.slice(2));
try {
  const definition = registry.find(args.command ?? '');
  if (definition === undefined) throw new UsageError(`Unknown command: ${args.command}`);
  const outcome = await runCommand(definition, args, { host, output, payer: servePayer });
  process.exitCode = outcome?.exitCode ?? 0;
} catch (err) {
  const { errorCode, exitCode } = classifyError(err, registry);
  console.error(`${errorCode}: ${err.message}`);
  process.exitCode = exitCode;
}
```

`node my-cli.mjs contract inspect --path ./my-dapp` lists the compiled contract's circuits; in a folder with no compiled contract it ends with `CONTRACT_NOT_COMPILED` and exit code 1. A test in mn runs the block above as it is written.
